# 周边去哪儿 · 高德地点推荐助手

## 何时使用

用户询问某个起点附近的地点，并可能带有以下约束时使用本 Skill：

- 地点类型：咖啡馆、餐厅、公园、书店、景点、便利店等
- 步行时间上限：例如“步行不超过 15 分钟”
- 推荐数量：例如“推荐最多 3 家”
- 排序偏好：例如“优先近一点”“安静一点”“适合带孩子”

如果用户没有给起点坐标，先用 `maps_geo` 把用户给的地址/地标转成 GCJ-02 坐标；如果给了明确坐标，直接使用，不要重复地理编码。不要使用设备定位，也不要自行编造坐标。

## 可用高德工具

只使用评测环境提供的高德 MCP 工具，不调用其他地图/搜索服务：

- `maps_around_search`：周边 POI 搜索
  - `keywords`：地点类型/关键词，如“咖啡馆”
  - `location`：中心点，格式 `"经度,纬度"`（GCJ-02）
  - `radius`：搜索半径，单位米
  - `types`：可选 POI 类型
  - `offset`：每页数量，默认 20
  - `page`：页码，默认 1
- `maps_direction_walking`：步行路线规划
  - `origin`：起点 `"经度,纬度"`
  - `destination`：终点 `"经度,纬度"`
- 可选：`maps_geo`（地址转坐标）、`maps_search_detail`（补充地址/类型）、`maps_regeocode`（坐标转地址）。

工具返回的 POI 列表通常包含 `name`、`address`、`location`、`distance`、`type`、`id`；路线结果包含 `route.paths[].distance`（米）和 `route.paths[].duration`（秒）。以实际返回字段为准，不要假设不存在的字段。

## 处理流程

### 1. 解析需求

从用户输入中提取：

- 城市/起点：明确的地址或坐标；坐标格式统一为 `"lng,lat"`。
- 地点类型：映射为一个简短关键词（“咖啡” → “咖啡馆”；“吃饭” → “餐厅”）。
- 步行上限 `max_walk_min`：没有明确说明时按 20 分钟处理，并在回答中说明这是默认值。
- 推荐数量 `limit`：默认 3，最多 3（题目要求最多 3 个）。
- 偏好：最近优先、安静、适合某类人群等；只有工具数据能支持时才作为排序理由。

### 2. 周边搜索

1. 根据步行上限估算初始半径：`radius ≈ max_walk_min × 80` 米，最小 300 米，最大 3000 米。
2. 调用 `maps_around_search`：
   ```json
   {
     "keywords": "咖啡馆",
     "location": "120.155070,30.274084",
     "radius": 1200,
     "offset": 20,
     "page": 1
   }
   ```
3. 如果结果少于 `limit`，可把半径扩大到 1.5 倍再查一次；最多扩大一次，避免无限循环。
4. 如果用户要求的是明确的 POI 类型，可同时传 `types`；不确定时不要传，依靠 `keywords`。

### 3. 初筛候选

从返回 POI 中：

- 去掉重名/同一 `id` 的重复项。
- 去掉明显不符合类型的项（例如搜“咖啡馆”却返回加油站）。
- 优先保留有 `address` 和 `location` 的项。
- 不要用 POI 返回的 `distance` 直接当步行距离；它只是直线/搜索距离，最终必须用步行路线校验。
- 候选最多取 8 个，避免对每个结果都调用路线规划造成超时。

### 4. 步行路线校验

对每个候选调用：

```json
{
  "origin": "120.155070,30.274084",
  "destination": "候选 POI 的 location"
}
```

从结果中取第一条可用步行方案：

- `distance_m = route.paths[0].distance`
- `duration_s = route.paths[0].duration`
- `walk_min = ceil(duration_s / 60)`（或按返回精度四舍五入，回答中注明“约”）

硬性规则：

- `walk_min > max_walk_min` 的候选不能作为“符合条件”的推荐。
- 路线查询失败/无路线的候选直接剔除，不能拿直线距离替代。
- 只能推荐实际调用过步行路线且满足时间上限的地点。

### 5. 排序与推荐理由

- 用户说“优先近一点”时，按 `walk_min` 升序，再按 `distance_m` 升序。
- 用户没有偏好时，按步行时间升序。
- 推荐理由只能引用已获得的数据：
  - 可以写：“步行约 8 分钟（约 560 米），是候选中最快的。”
  - 可以写：“地址为 …，类型为 …，符合咖啡馆需求。”
  - 不能编造“人少”“安静”“排队短”“营业中”等未核实信息；如用户在意，明确写“未核实”。
- 最多返回 `limit` 个；不足时如实说明，例如“15 分钟步行范围内只找到 2 家符合条件的咖啡馆”。

### 6. 输出格式

用 Markdown 表格或列表返回，至少包含：

| 地点 | 地址 | 步行距离/时间 | 推荐理由 |
|---|---|---|---|
| 名称 | 高德返回的地址 | 约 X 米 / 约 Y 分钟 | 仅基于路线和 POI 数据 |

表格后补充一句简短说明：

- 数据来源：高德地图（周边搜索 + 步行路线规划）。
- 若使用了扩大半径/默认步行上限，明确说明。
- 若结果不足、查询失败或信息缺失，说明原因和可放宽的条件。

## 异常与边界

- **没有结果**：先扩大半径一次；仍无结果则回答“该范围内未找到符合条件的地点”，可建议放宽类型或步行时间，不要编造地点。
- **路线失败**：剔除该候选，并在回答中说明“有候选因步行路线查询失败未列入”。
- **POI 信息缺失**：地址缺失时写“地址未返回”，不要补写。
- **用户要求超过 3 个**：最多给 3 个，并说明题目/推荐上限。
- **用户要求驾车/公交**：本 Skill 只处理步行；可以说明当前只提供步行方案，不伪造驾车时间。
- **坐标是 WGS-84**：高德使用 GCJ-02；若用户明确说 GPS/WGS-84，先用高德坐标转换能力转换，或在回答中说明坐标系差异，不能直接混用。

## 示例

用户：“我在杭州西湖文化广场（120.163,30.278），想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。”

执行：

1. `maps_around_search(keywords="咖啡馆", location="120.163,30.278", radius=1200, offset=20)`
2. 取最多 8 个候选，逐个 `maps_direction_walking(origin="120.163,30.278", destination=候选坐标)`
3. 过滤 `walk_min <= 15`，按步行时间升序，取 3 个
4. 输出表格；若不足 3 个，说明“15 分钟内仅找到 N 家”。

注意：示例中的坐标仅用于说明格式；实际回答必须使用本次工具返回的地点、地址和路线数据。
